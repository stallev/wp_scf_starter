# Регламент HTML-прототипа

Как писать прототип, чтобы десятая страница стоила столько же, сколько вторая, и чтобы блоки переносились в шаблоны WordPress без переписывания. У каждого правила — что ломается при нарушении. Прототип лежит в корневом `prototype/` (read-only для агента, на прод не уезжает); образец — [`fixtures/demo-prototype/`](../../fixtures/demo-prototype/). Машинно проверяемая часть — `npm run lint:prototype` (таблица в конце).

## 1. Файлы

```
<slug>.html            одна страница = один файл; имя = будущий slug URL
assets/css/main.css    единственный файл стилей
assets/js/main.js      поведение UI
assets/fonts/          локальные woff2
assets/images/         картинки (с размерами)
```

- Новых CSS/JS-файлов не создавать: стили страницы — секция `/* ============ PAGE: <NAME> ============ */` в конце `main.css`, поведение — новый модуль в `main.js`. *Почему:* один `main.css` = один стиль темы без спора о порядке каскада.
- Ссылки между страницами — относительные (`contacts.html#lead`), чтобы прототип кликался локально; при переносе их заменяют URL из `pages-map`.
- Данные, которые в WordPress станут полями (NAP, цены, FAQ), не грузить `fetch('data/*.json')`: в WordPress это 404 (K9). В разметке — видимые значения, их при переносе заменяют провайдеры.

## 2. CSS

- **Токены** — единственный источник значений: цвета, шрифты, размеры, отступы, радиусы, тени, тайминги в `:root` (`--c-*`, `--font-*`, `--fs-*`, `--sp-*`, `--r-*`, `--t-*`). Сырой hex / px в компоненте — только точечное значение одного компонента; понадобилось второй раз — токен. *Почему:* при переносе меняются значения токенов, а не правила компонентов.
- **БЭМ без вложенности:** `.block`, `.block__element`, `.block--modifier`, один класс в селекторе. Допустимо: контекст темы (`.section--dark .section__eyebrow`) и состояние (`.faq__item.is-open .faq__a`). *Почему:* блок переносится куском разметки и не зависит от окружения.
- **Состояния — только `is-*`** (`is-open`, `is-active`, `is-sent`, `is-stuck`). JS переключает классы и ARIA, внешний вид inline-стилями не пишет (исключение — вычисляемые величины вроде смещения слайдера).
- **DRY-лестница** перед новым элементом: 1) есть компонент — используй; 2) почти подходит — модификатор; 3) отличается 2–3 свойствами — общая база групповым селектором + различия; 4) только потом новый компонент, сразу переиспользуемый. Признаки нарушения: два селектора с одинаковым набором фона / радиуса / тени / отступов; копия блока под новым именем «для другой страницы».
- **Порядок секций:** FONTS → TOKENS → BASE → LAYOUT → компоненты → брейкпоинты → `PAGE: <NAME>` → UTILITIES (последней). `!important` запрещён (кроме утилит и reduced motion) — если «нужен», сломан порядок каскада.
- **Mobile-first**, брейкпоинты `min-width: 600px` и `1024px`, других нет. Сетки — `grid` + `gap`, расстояние между соседями — `gap` родителя, не `margin` детей (блок цел при перестановке в CMS).
- **Вендорные префиксы вручную и только где без них не работает:** `appearance`, `backdrop-filter` (`-webkit-`), `position: sticky` (`-webkit-sticky`), `user-select`, `text-size-adjust`, `::selection` / `::-moz-selection`, бегунок `input[type=range]`, fallback-строка перед `env(safe-area-inset-*)`. Префиксное объявление — раньше стандартного. Не префиксовать `transform`, `transition`, `flex`, `grid`, `gap`, `object-fit`, `clamp()`.

## 3. HTML

- Один `<h1>`; дальше `h2` для секций, `h3` в карточках, уровни не перескакивать.
- Секция — `<section class="section …" id="…">`: на `id` ссылаются меню и кнопки. Семантика: `<nav>`, `<main>`, `<footer>`, `<button type="button">`.
- `<img>` всегда с `alt` (описание объекта, не ключевое слово; `alt=""` — декоративная), `width` и `height`. LCP-картинка — `fetchpriority="high"`, ниже сгиба — `loading="lazy"`.
- **Доступность:** контраст ≥ 4.5:1 (крупный текст ≥ 3:1), цели касания ≥ 44×44 px, `aria-expanded` у аккордеона, `aria-label` у иконок-кнопок, `<label for>` у каждого поля, статус отправки — `role="status"`, `:focus-visible` не отключать.
- **SEO-набор страницы в прототипе:** `<title>`, description, canonical, OG, крошки, schema по типу страницы (Service / FAQPage / LocalBusiness …). Тексты — из спецификации страницы ([`project/pages/_template.md`](../project/pages/_template.md)), не придумываются при вёрстке. Текст FAQPage = видимый текст. В WordPress этот набор отдаёт Yoast ([`contracts/seo.md`](../contracts/seo.md)).
- **Прототип ≠ прод:** на каждой странице `<meta name="robots" content="noindex, nofollow">`, снимается одним проходом перед публикацией. Служебные страницы (для владельца, не для клиентов) — `noindex` навсегда, без schema и без лид-формы, помечены в меню.
- **Заглушки помечены:** фото — комментарием `<!-- ЗАГЛУШКА: … -->`, текст — видимой пометкой «уточняется», неизвестная цифра — `___`. Выдуманных цифр в прототипе нет. Перед сдачей поиск по `___` и `ЗАГЛУШКА` показывает, что ждёт заказчика.
- Ни один блок не повторяет блок другой страницы (дословно или пересказом): страницы с одним смыслом конкурируют в выдаче.

## 4. Формы

- На странице **ровно одна** `<form class="lead-form js-lead" id="…" novalidate>` (ближе к подвалу) с блоками `__fields`, `__submit`, `__legal`, `__done`; служебные страницы — без формы. Остальные CTA — карточка «позвонить / написать» (тот же вид, `<div>` без полей и без `js-lead`) со ссылкой на `id` формы. Контракт в WordPress — [`contracts/forms.md`](../contracts/forms.md).
- `id` полей — с префиксом формы (`lead-name`), иначе `label for` цепляется к чужому полю. Чекбокс согласия не предзаполнен, ссылка на политику — новая вкладка.
- Все якоря, на которые ведут кнопки и меню, существуют; у целей якорей — `scroll-margin-top: var(--header-h)`, иначе липкая шапка перекрывает верх блока при переходе по ссылке.
- Плавающий лейбл держится на `placeholder=" "` — не заменять его текстом.

## 5. JavaScript

- Один модуль на фичу с защитным выходом, если разметки нет (`if (!el) return;`), и изоляцией ошибок: один `main.js` на всех страницах, отсутствие блока не роняет меню.
- DOM ищется по `id` или `js-*`-классу; классы оформления — не хуки JS.
- Один стиль синтаксиса на файл (не смешивать ES5 и ES2015+ в одном файле).
- Без библиотек и сборщиков; без `innerHTML` с данными пользователя, без `scrollIntoView`, без `localStorage` без явной необходимости; анимации — CSS + классы.
- **Прогрессивное улучшение:** без JS весь текст виден (FAQ открыт, `.reveal` не прячет контент).

## 6. Производительность (с первого дня)

- Первый экран (H1, лид, CTA, LCP-картинка) — **без `.reveal`** (K1).
- Шрифты — локальные woff2, без Google Fonts и чужих CDN; `@font-face` в начале `main.css`.
- Тяжёлые встраивания (карта, видео, виджет) — фасад: заглушка с `aspect-ratio`, iframe по клику.
- Никаких `style=""` (кроме custom properties вида `style="--d:120ms"`) и `on*=`-обработчиков.

Подробнее и почему — [`performance.md`](performance.md).

## 7. Что проверяет `lint:prototype`

[`tools/lint-prototype.mjs`](../../tools/lint-prototype.mjs), по умолчанию каталог `paths.prototype`; негативная фикстура — [`fixtures/bad-prototype/`](../../fixtures/bad-prototype/).

| Правило | Уровень |
|---|---|
| `style=""` с чем-то кроме custom properties | ошибка |
| Inline-обработчики `on*=` | ошибка |
| Стили не из локальных `assets/`, `@import` удалённого CSS, любые font-CDN | ошибка |
| `<img>` без `width`, `height` или `alt` | ошибка |
| Не ровно один `<h1>`; `<h1>` внутри `.reveal` | ошибка |
| Больше одной `form.js-lead`; для страницы из `pages-map` — число форм ≠ `lead_form` | ошибка |
| `lcp.selector` не найден или в `.reveal`; блок `above_fold` в `.reveal` | ошибка |
| Класс не похож на БЭМ / `is-*` / `js-*` | предупреждение |

Токены, DRY, иерархия заголовков, доступность, SEO-набор и тексты — ручная приёмка на фазе 1 ([`phases/phase-1-prototype.md`](../phases/phase-1-prototype.md)).

## 8. Чек-лист сдачи страницы

- [ ] `npm run lint:prototype` зелёный.
- [ ] Нет новых CSS/JS-файлов; стили — секция `PAGE:`, поведение — модуль с защитным выходом.
- [ ] Значения из токенов; новые элементы — переиспользование или модификатор.
- [ ] Одна `form.js-lead` (или ни одной на служебной); ранние CTA — карточка звонка со ссылкой на форму.
- [ ] Один `h1`, корректная иерархия; SEO-набор = спецификация страницы.
- [ ] Заглушки помечены, `___` там, где нет данных; `noindex` на месте.
- [ ] 360 / 768 / 1440 px без горизонтального скролла; клавиатура проходит все элементы; консоль без ошибок.

## 9. При конфликте правил

Спецификация / семантика страницы важнее регламента. Правило мешает задаче — задача решается, отклонение фиксируется комментарием с причиной (молчаливое отклонение = дефект). Правило понадобилось второй раз — дописывается сюда; машинно проверяемое — в `lint:prototype`.

## Деплой прототипа на Vercel (опционально)

Для показа заказчику: Settings → General → **Root Directory** = `prototype` (без слешей), Framework Preset — Other, Build / Install не нужны; `vercel --cwd prototype` (превью), `--prod`. На время работы в `vercel.json` можно отдать `Cache-Control: no-store`, чтобы правки были видны сразу; перед показом «как прод» — нормальный кэш для `/assets/`. Прототип остаётся `noindex`.
