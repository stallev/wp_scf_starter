# Архитектура: принципы и почему

Интерфейсы — в контрактах ([`mu-plugin.md`](../contracts/mu-plugin.md), [`theme.md`](../contracts/theme.md), [`data-structures.md`](../contracts/data-structures.md)); решения с датами — [`STARTER-PLAN.md`](../STARTER-PLAN.md) §6. Здесь — почему слои разделены именно так.

## Слои

```text
project.config.json, pages-map.json ──build:config──▶ starter-core/config.generated.php
                                                           │
Yoast (title, meta, sitemap, базовый граф)                 ▼
        ▲                         mu-plugin starter-core: CPT, SCF-поля и опции, провайдеры
        │ graph pieces            starter_get_*(), формы и лиды, seed, llms.txt, схемы
        └──────────────────────────────┤
                                       ▼ только через API
                        тема starter: шаблоны, parts, enqueue, starter_image(), <head>, GA4
```

| Слой | Где | Делает | Не делает |
|---|---|---|---|
| Конфиг | корень репо → снимок PHP | Параметры проекта и манифест страниц | Не деплоится (снимок — да) |
| Данные и логика | `starter-core` | CPT, поля, опции, провайдеры, формы, seed, SEO-сущности | Front-end enqueue, разметка страниц |
| Представление | тема | HTML, CSS/JS, изображения, `<head>`-оптимизации | Регистрация CPT / полей, SQL в шаблонах, литералы данных |
| SEO-мета | Yoast | Title, description, canonical, OG, sitemap, базовый граф | — |
| Бизнес-модули | `starter-core/modules/<name>` | Каталог, прайс-калькулятор (выключены по умолчанию) | Не ломают ядро при выключении |

## Принципы

1. **Mu-plugin = данные, тема = представление.** *Почему:* смена темы или редизайн не теряет данные; mu-plugin нельзя случайно деактивировать; зоны проверяемы (`check:naming`: enqueue в ядре запрещён).
2. **Провайдер вместо запроса в шаблоне.** Шаблон зовёт `starter_get_*()`; провайдер знает поля, порядок, fallback и кэш (`static` на запрос, transient + инвалидация на сохранении для дорогих выборок). *Почему:* кейс исходного проекта — телефон захардкожен в 8 шаблонах при готовом провайдере; теперь это ловит `check:hardcode` (K17).
3. **Поля SCF в PHP, по name.** Одна группа — один файл; SCF UI только редактирует значения. *Почему:* поля видны агенту в коде и в diff, не живут только в базе; чтение по key ломается при пересоздании группы (K13).
4. **Параметризация, а не копия проекта.** Префикс, slug-и, домены, шрифты, размеры — `project.config.json`; `npm run init` переименовывает стартер один раз. Default-ID клиентов (GA4 и т. п.) в код не попадают.
5. **`pages-map.json` — центральный манифест.** Один список страниц питает сидер, SEO (`noindex`, схемы), тему (форма, первый экран), e2e, PSI, `lint:prototype`, `llms.txt`. *Почему:* в исходном проекте списки URL в тестах, PSI и сидере были захардкожены по отдельности и расходились (D7).
6. **Снимок конфига для PHP.** Корень репо не деплоится, поэтому `build:config` пишет `config.generated.php`, а `check:config` ловит несвежий снимок (D22).
7. **Прототип вне темы.** `prototype/` в корне: эталон переноса и визуального diff, но не уезжает на прод (D10).
8. **Бизнес-специфика — модулем.** Каталог с фильтрами и прайс → калькулятор — образцы паттернов, а не ядро (D11).
9. **Seed идемпотентен.** Запись ищется по стабильному slug, второй прогон = без изменений; секреты в seed запрещены.
10. **Блог — `post` + `category`.** Отдельный CPT не нужен (`check:naming`: `blog-cpt`).
11. **Проверки вместо текста.** Всё машинно проверяемое — `tools/check-*` и `gate:*`; документ хранит решения и «почему». Повторённая агентом ошибка → новая проверка.

## Плагины

| Плагин | Роль |
|---|---|
| Secure Custom Fields | UI значений полей; группы регистрируются в PHP ядра |
| Yoast SEO | Мета, sitemap, граф schema.org |

Версии — `project.config.json` → `wordpress` (`latest` = последняя стабильная, D17); плагины ставит wp-env, а не копии в репо (D13). Без headless, без page builder-ов, без block theme (D1).

## Безопасность (база)

Escape на выводе, sanitize на вводе, nonce + capability на каждом действии; форма — nonce + honeypot + rate limit; лиды непубличны; секреты — `.env` или защищённые опции с `autoload=false`, не в git и не в seed.
