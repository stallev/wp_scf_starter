# `docs/project/` — документы конкретного проекта

Шаблоны, которые заполняются на реальном проекте. В стартере — `status: planned`; заполненный документ проекта получает `status: canonical` и дату. По приоритету источников (см. [`docs/INDEX.md`](../INDEX.md)) эти документы — уровень **Project**: при конфликте с контрактами стартера побеждают они, но расхождение фиксируется правкой документа.

## Что заполнить и когда

| Файл | Фаза | Что |
|---|---|---|
| [`sitemap.md`](sitemap.md) | 0–1 | Карта страниц, приоритеты, компоненты, журнал решений. Технический манифест — `pages-map.json` |
| [`seo-strategy.md`](seo-strategy.md) | 0–1 | Интенты, конкуренты, приоритизация, локальное SEO, метрики |
| [`pages/_template.md`](pages/_template.md) → `pages/<slug>.md` | 1 | Спецификация страницы; проверка — [`pages/_checklist.md`](pages/_checklist.md). Путь — в `specs` записи `pages-map` |
| [`seo/meta-patterns.md`](seo/meta-patterns.md) | 1, 6 | Паттерны и итоговая таблица title / description |
| [`seo/post-outline.md`](seo/post-outline.md) → `seo/posts/<slug>.md` | 6+ | Outline статьи блога + правила текста |
| [`prds/_template.md`](prds/_template.md) → `prds/<feature>.md` | 2 | Требования к бизнес-фиче сверх стартера |
| [`test-cases/_template.md`](test-cases/_template.md) | 5–7 | Ручные кейсы сверх e2e |
| [`manager-guide.md`](manager-guide.md) | 7 | Памятка менеджеру сайта |
| [`qa-report.md`](qa-report.md) | 7 | Итог регресса и чеклиста запуска |
| [`perf-log.md`](perf-log.md) | 7+ | Журнал вех PSI |
| [`llms.txt.md`](llms.txt.md) | 6 | Где правится `/llms.txt` |

## Правила

- Один факт — одно место: тексты страниц — здесь, NAP — опции «Компания», список URL — `pages-map.json`. Документ ссылается, а не копирует.
- Данные заказчика, которых нет (цифры, фото, ответы), — раздел «Что нужно от заказчика» в спецификации, в тексте — `___`.
- Секреты, пароли, персональные контакты заказчика — не в репо.
- Шаблон не подходит проекту — правится копия проекта; улучшение, полезное всем, — PR в стартер.
