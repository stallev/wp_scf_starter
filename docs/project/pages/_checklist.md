# Чек-лист спецификации страницы

Прогонять каждую `pages/<slug>.md` до вёрстки / переноса. Пункт не выполняется намеренно — это решение в спецификации, а не пропуск.

1. **Один интент.** Страница соответствует одной строке карты интентов ([`seo-strategy.md`](../seo-strategy.md)); пересечение со смежной страницей описано — чем отличается заголовок, оффер, аудитория.
2. **Нет каннибализации и thin content.** Ни один блок не пересказывает блок главной или другой страницы; есть хотя бы один блок, которого нет на главной.
3. **Гео без doorway.** Гео-конкретика — блок на существующей странице, не отдельный URL на каждый город без уникального контента; исключённые топонимы не в заголовках.
4. **Позиционирование** соответствует бизнес-вводным (основной сегмент подан как основной).
5. **Цена честно.** Переменная стоимость — «от» + из чего складывается; фиксированный тариф — цифрой без «от»; неизвестная цифра — `___` и пункт «нужно от заказчика».
6. **CTA и форма.** Ранняя CTA-точка есть; на длинной странице — ≥ 2 точек; форма ровно одна (или ни одной на служебной), карточки звонка ведут на неё.
7. **SEO-параметры заполнены:** title, description, H1, URL, schema по типу, 2–4 целевых кластера.
8. **Перелинковка конкретна:** исходящие и входящие URL названы; развилка между смежными интентами есть.
9. **Глубина соразмерна приоритету** страницы; лёгкие шаблоны не раздуты.
10. **Что нужно от заказчика** — отдельный раздел; пустой = «всё есть», а не «забыли».
11. **Первый экран** описан (LCP, `above_fold`) — это пойдёт в `pages-map.json`.
