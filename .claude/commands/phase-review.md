# /phase-review — независимое ревью

Цель: `$ARGUMENTS` (base-ref для diff, например `master`, или phase-файл; пусто — незакоммиченные изменения).

**Ревьюер — не тот агент, который реализовал.** Запускать отдельным subagent (или другой моделью); автор изменений в ревью не участвует. Ревьюер ничего не правит — только находит и доказывает.

## Вход

1. Diff: `git diff <base>` (рабочее дерево против базы, включая незакоммиченное) + неотслеживаемые файлы из `git status --porcelain` (строки `??`) — прочитать их целиком.
2. AC задач фазы (Happy / Negative / Security) из phase-файла или задачи.
3. Правила зон изменённых файлов: `.cursor/rules/*.mdc` по glob + [`AGENTS.md`](../../AGENTS.md).

## Шаги

1. **Gate:** выполнить команды фазы (минимум `npm run gate:0`; фазы проекта — `gate:1`…`gate:7`, страницы — `gate:page -- <url>`; e2e-наборы Playwright входят в них). Красный gate = вердикт `BLOCK` без дальнейших оправданий.
2. **AC:** каждый AC — выполнен / не выполнен / не проверяем, со ссылкой на код или вывод команды.
3. **Корректность:** ошибки логики, граничные случаи, escaping/sanitize/nonce/capabilities, идемпотентность seed, инвалидация кэшей.
4. **Инварианты `AGENTS.md`:** зоны mu-plugin/тема, данные через API, имена из словаря, Yoast-only SEO, одна `form.js-lead`, `.reveal` и LCP по `pages-map`, `strategy` у скриптов, `starter_image()`, `prototype/` не тронут, нет секретов.
5. **Сверка с документацией** — процедура `/doc-align` (`.claude/commands/doc-align.md`) на diff.
6. **Проверяемость:** повторяющаяся ошибка — предложить автоматическую проверку, а не правило в тексте.

## Вывод

```text
VERDICT: PASS | PASS WITH NOTES | BLOCK
Gate: <команда → код выхода>
AC: <n/m выполнено; невыполненные списком>

Findings (самые серьёзные первыми):
1. [blocker|major|minor] <файл:строка> — <что не так> → <сценарий сбоя> → <как исправить>
```

Блокеры закрываются до перехода к следующей фазе; после исправлений — повторный `/phase-review`.
