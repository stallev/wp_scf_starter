# /doc-align — сверка с документацией

Цель: `$ARGUMENTS` (phase-файл, задача или область; пусто — текущий diff `git diff` + незакоммиченные файлы).

Запускается **при старте** фазы (до кода) и **до закрытия** её gate. Без сверки следующую фазу не начинать. Cursor вызывает ту же процедуру, прочитав этот файл.

## Источники

Порядок при конфликте и статусы — **только** [`docs/INDEX.md`](../../docs/INDEX.md): прочитать его, не полагаться на память. Минимальный набор для сверки:

- запись страницы в `pages-map.json` и `project.config.json`;
- «Связанные документы» phase-файла ([`docs/phases/`](../../docs/phases/ROADMAP.md)) и контракты из них;
- словарь имён — [`docs/contracts/naming.json`](../../docs/contracts/naming.json);
- `prototype/` — для разметки и контента страниц.

## Чеклист

1. Прочитать связанные документы фазы / задачи и релевантные контракты целиком, а не по памяти.
2. Scope: URL, сущности, поля, UX-блоки, формы, SEO — ровно то, что есть в `pages-map`, контрактах и прототипе; ничего сверх.
3. Имена: каждое новое имя есть в `naming.json`; `npm run check:naming` зелёный.
4. Данные: в шаблонах нет литералов NAP / цен / домена — только API `starter_get_*()`.
5. SEO-тексты и спецификации страниц не копируются в код и docs — ссылка на источник.
6. Контракт меняется — сначала документ (с датой `updated`), потом код; расхождение без правки документа = блокер.
7. Ссылки и покрытие правилами: `npm run check:links`, `npm run check:rules`.
8. Итог — в отчёт фазы: что сверено, какие расхождения найдены, как закрыты (правка документа или кода).

## Анти-паттерны

```text
❌ Код или seed «по памяти / как в прошлом проекте» без сверки с naming.json и pages-map
❌ Новые URL, CPT, options, поля, хуки вне контрактов и словаря
❌ Молчаливое расхождение: код поменяли, контракт нет (или наоборот)
❌ Пересказ правила приоритета или статусов вместо ссылки на docs/INDEX.md
❌ Закрытие gate без чтения связанных документов фазы
❌ Правка prototype/ «чтобы совпало»
```

## Вывод

```text

Сверено: <документы>
Расхождения: <файл:строка → документ, решение> | нет
```
